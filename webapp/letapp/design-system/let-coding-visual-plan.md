# Let Coding 苹果式科技简约视觉规范

> 状态：设计计划
>
> 范围：全站视觉系统；第一批实现重点为 `MainLayout.vue`、`style.css` 和 `Home.vue`。
>
> 原则：只改变视觉层、交互反馈和响应式呈现，不改变路由、认证、接口和业务数据行为。

## 1. 产品定位

Let Coding 是面向学生与开发者的在线判题和学习工作台。视觉方向定位为：

**Apple 式系统界面层次 + 精密编码工具的技术感。**

浅色主题作为默认入口，深色主题保留为编码场景的专注模式。终端编辑器是首页唯一重点视觉，绿色代表运行成功/通过/在线，青色代表当前焦点和交互，不使用泛用蓝色 SaaS 视觉。

## 2. Design Tokens

### 2.1 色彩

#### Light

| Token | Value | 用途 |
| --- | --- | --- |
| `--color-background` | `#F6F7F9` | 页面背景 |
| `--color-foreground` | `#111827` | 主标题、正文 |
| `--color-muted-foreground` | `#5B6472` | 次要文本、辅助说明 |
| `--color-surface` | `#FFFFFF` | 面板、输入框、浮层 |
| `--color-border` | `#D8DEE6` | 分隔线、边框 |
| `--color-signal` | `#19C37D` | 通过、成功、在线、运行完成 |
| `--color-accent` | `#0EA5B7` | 当前导航、链接、编辑器焦点 |

#### Dark

| Token | Value | 用途 |
| --- | --- | --- |
| `--color-background` | `#080B10` | 页面背景 |
| `--color-foreground` | `#F3F6F8` | 主标题、正文 |
| `--color-muted-foreground` | `#9AA7B3` | 次要文本 |
| `--color-surface` | `#10161D` | 面板、输入框、浮层 |
| `--color-border` | `#26323C` | 分隔线、边框 |
| `--color-signal` | `#19C37D` | 通过、成功、在线、运行完成 |
| `--color-accent` | `#38C6D4` | 当前导航、链接、编辑器焦点 |

颜色规则：

- 绿色只表示正向状态，不用于普通装饰。
- 青色用于交互强调，不与成功状态混用。
- 错误、警告和进行中状态分别使用可区分的红色、琥珀色和中性灰，不依赖红绿差异传达唯一信息。
- 禁止大面积渐变、装饰性光晕、赛博朋克扫描线和无意义网格背景。

### 2.2 字体

- UI 与中文：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "Inter", "Noto Sans SC", sans-serif`
- 代码、文件路径、判题状态：`"JetBrains Mono", ui-monospace, monospace`
- 正文最小字号 16px；辅助标签不低于 12px。
- 标题通过字号、字重和间距建立层级，不使用全大写标签或单词染色。
- 长文本控制在 70–80 个字符以内，行高保持 1.5 左右。

### 2.3 形态与间距

- 页面区块通过留白、分隔线和层级表达，不把所有内容拆成卡片。
- 普通卡片最大圆角 8px；终端工具允许 10–12px 圆角。
- 阴影只用于浮层和终端工具，使用低扩散、低不透明度阴影。
- 使用 4/8px 间距节奏；相邻触控目标至少间隔 8px。
- 所有主要交互控件最小触控区域 44px。
- 内容最大宽度维持 1360px，桌面端根据断点增加外边距。

## 3. 页面布局

### 3.1 桌面端

```text
┌────────────────────────────────────────────────────────────────────┐
│ logo │ 首页 题库 学习 编辑器 比赛 排行榜 讨论 公告 │ 搜索 ◐ 登录/用户 │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  写代码，更加顺手                         ┌──────────────────────┐  │
│  在线编写、运行和提交代码                 │ playground/main.cpp │  │
│  [进入编辑器] [学习资源]                  │ code     result     │  │
│                                           │ languages / run     │  │
│                                           └──────────────────────┘  │
├────────────────────────────────────────────────────────────────────┤
│ 继续学习 / 最近活动 / 难度分布                                      │
└────────────────────────────────────────────────────────────────────┘
```

- 顶部导航固定高度 64px，主内容预留同等上边距。
- Hero 左侧为标题、说明和主要操作，右侧为可点击的终端工具。
- 终端工具是首页唯一重点视觉；不再叠加装饰性大网格、漂浮代码符号或多组光效。
- 仪表盘信息顺序固定为：行动条 → 指标横排 → 两列活动 → 难度分布。

### 3.2 移动端

- 使用紧凑顶栏与抽屉导航，保留现有导航入口和返回逻辑。
- Hero、终端、操作按钮纵向排列，按钮在小屏幕上变为整行布局。
- 代码终端内部在窄屏下由左右分栏切换为上下堆叠。
- 禁止横向滚动；表格、列表和状态标签需要有可读的收缩/截断策略。

## 4. 组件规则

### `MainLayout.vue`

- 统一 logo、导航、搜索框、主题切换、用户菜单和移动抽屉的 token。
- 当前路由同时通过文字权重、短底线和轻微背景区分，不能只依赖颜色。
- 保留语义化的 `header`、`nav`、`main`、`button` 结构及现有认证逻辑。
- 浮层使用统一的 surface、border 和阴影，不再为每个菜单单独定义颜色。

### `style.css`

- 将页面级硬编码颜色集中为 light/dark CSS 变量。
- 保留 `ui-btn`、`ui-card`、`ui-input`、`ui-badge`、`ui-table` 等公共类名，避免业务页逐页重写。
- 统一按钮的 hover、pressed、disabled 和 focus 状态。
- 统一表格、空状态、骨架屏、输入框、徽章和分页的密度与对比度。
- 全局字体切换到系统 UI 字体；代码区域使用 JetBrains Mono 或系统等宽回退。

### `Home.vue`

- 删除泛用蓝色和装饰性大网格，保留代码终端作为品牌记忆点。
- Hero 标题、按钮、运行状态、学习进度和活动列表使用同一套视觉层级。
- 终端内继续使用代码颜色区分语义；运行状态采用绿色、青色、琥珀色和中性灰的组合，不依赖红绿单色差异。
- 仪表盘区块以平面分组和分隔线为主，避免卡片嵌套卡片。

### 主题行为

- 无已保存偏好时默认使用浅色主题。
- 已保存的深色偏好继续生效，主题切换按钮保留并提供明确的 `aria-label`。
- 系统主题不覆盖用户已明确选择的浅色或深色偏好。

## 5. Accessibility 与交互

- 所有图标按钮提供 `aria-label`；菜单、导航和主题按钮暴露展开/选中状态。
- Tab 顺序与视觉顺序一致，所有可操作元素拥有至少 2px 的可见 focus ring。
- 页面切换、抽屉、下拉菜单和首页入场动画支持 `prefers-reduced-motion`。
- 搜索、导航、表格、空状态和加载骨架不依赖 hover 才显示关键信息。
- 浅色和深色正文对比度均达到 4.5:1；边框、徽章、焦点和禁用状态单独验证。
- 颜色不是唯一状态信号；成功、错误、警告和进行中状态同时使用文字或图标。
- 固定导航不得遮挡键盘焦点或页面首个内容区。

## 6. 实施顺序

1. 在 `style.css` 建立新的 light/dark token、字体、间距、focus 和通用组件状态。
2. 在 `MainLayout.vue` 替换导航、搜索、菜单、抽屉和主题控件的视觉层，同时保持现有事件和认证逻辑。
3. 在 `Home.vue` 重做 hero、终端外框和仪表盘区块的视觉样式，保留数据加载和路由行为。
4. 扫描其他页面中的硬编码颜色，逐步迁移到公共 token，避免改造后出现旧蓝色残留。

## 7. 验收清单

### 视觉与响应式

- [ ] 375px、768px、1024px、1440px 视口均无横向溢出。
- [ ] 移动端横屏下导航、终端和主要操作仍可用。
- [ ] 浅色、深色和系统减少动画模式均有清晰层次。
- [ ] 首页首屏只保留终端作为重点视觉，不出现无意义装饰层。

### 交互与无障碍

- [ ] 键盘可完成导航、搜索、主题切换、用户菜单、移动抽屉和首页 CTA。
- [ ] 所有 icon-only 按钮有可访问名称，当前导航和展开状态可被辅助技术识别。
- [ ] 所有主要控件触控区域至少 44px，控件间距至少 8px。
- [ ] focus ring 在浅色和深色背景上均清晰可见。
- [ ] `prefers-reduced-motion` 下不发生非必要位移动画。

### 回归与构建

- [ ] 认证、路由、搜索跳转、语言切换、终端点击和仪表盘数据行为不回归。
- [ ] `npm run build` 通过。
- [ ] 使用浏览器截图检查首页首屏、导航、终端和仪表盘没有遮挡、溢出或文字截断。

## 8. 范围假设

- 不引入新的 UI 框架或图标库，继续使用现有 Iconify、Tailwind 和 Naive UI。
- 不新增后端接口、路由、数据字段或认证流程。
- 第一批代码改造聚焦 `MainLayout.vue`、`style.css` 和 `Home.vue`；其他业务页通过公共 token 渐进迁移。
